## Why

Nothing in this repository checks that a compiled function answers what the same Python answers.

`tests/execution.rs` asserts 89 **hand-written** expected values — a number a person typed while
reading the rule they were implementing. That catches a backend that disagrees with what its author
believed; it cannot catch a backend that disagrees with Python, because Python was never consulted.
The one place a real oracle exists is `demo/src/algorithms/__main__.py`, which pairs fifteen
workloads with independently written interpreted answers and reports disagreements — and it found
three defects that every correctness test in the repository had passed over.

Fifteen workloads and eighteen accepted fixtures are the whole of it. The corpus is the smallest
part of the compiler and the one every later change leans on.

`inspiration/py2many/` gets this right in a way worth copying exactly. For every (case, language) it
transpiles, compiles, runs, and asserts the binary's stdout **byte-matches CPython running the same
source**; every case must print something. The consequence is the interesting part: a golden file is
only ever *written* after all three succeeded, so `tests/expected/` is self-certifying and its
support matrix, `LANGUAGES.md`, is generated by counting that directory and enforced by CI. Its
documentation cannot overstate its implementation, because the documentation is derived from
evidence of success.

compylr already owns every ingredient and has never assembled them. `tests/execution.rs` writes the
whole crate to a temp dir and shells `rustc`. `python/tests/test_end_to_end.py` builds through
maturin and asserts compiled against interpreted. `COMPYLR_DISABLE=1` makes any project run
interpreted all the way down. What is missing is the loop over the corpus.

**Why now.** This is a prerequisite, not an improvement. The changes queued behind it — a second
backend, a typed IR, and then growing the accepted subset with desugarings and stdlib intrinsics —
are each a claim that translated code still means what the Python meant. Adding them first means
adding them unverified, and the failure mode is the one this project is least able to tolerate: a
plausible wrong answer. The corpus is also where growth becomes measurable; without it, "the subset
got bigger" is a feeling.

## What Changes

- **Every accepted fixture gains a driver, and CPython becomes the oracle.** A driver
  (`python/fixtures/drivers/<name>.py`) imports the fixture's members, calls them over chosen
  inputs, and prints. No expected values are written anywhere: the same driver runs under CPython
  and against the translation, and the two transcripts must match. A fixture whose driver exercises
  nothing is a fixture that proves nothing, so a driver is required rather than optional.

- **Two tiers, because "compiled" means two different things.** A **native** tier emits the crate
  and runs it through `rustc` — seconds, no maturin, on every `cargo test`. A **bridge** tier builds
  through maturin and calls across PyO3 — minutes, `slow`-marked, in `make check`. They fail
  differently on purpose: the native tier catches a wrong translation, the bridge tier catches a
  wrong *conversion*, which is where a text argument costs ~42ns per element and made
  `binary_search` sixteen times slower than interpreted. Neither subsumes the other.

- **A compile failure is a failure.** py2many degrades a compile failure to `pytest.skip`, so
  compilability regressions are visible only in a skip count. This corpus does not: a fixture that
  stops compiling, stops running, or stops agreeing fails the suite. Skipping is reserved for a
  missing toolchain, which is a fact about the machine rather than about the program.

- **A robustness walk over real Python.** The frontend is run over a corpus far larger than the
  fixtures — this repository's own `python/compylr/`, `demo/src/`, and a pinned set of standard
  library modules — asserting only that every outcome is a lowered unit or a **located**
  diagnostic. Never a panic, never an unlocated error. It compiles nothing, so it costs seconds, and
  it reports the acceptance rate as a number.

- **The rejection corpus gains an inverted guard.** Today `python/fixtures/rejected/` proves that 59
  constructs are refused. As the subset grows some of them will start lowering, and that must be a
  recorded decision rather than a quiet one: a rejected fixture that begins to lower fails the suite
  until it is moved and given a driver.

- **The README's subset claim becomes generated.** `scripts/update_benchmarks.py` already rewrites
  blocks between `<!-- benchmark:NAME -->` markers and has a `--check` mode wired into CI and the
  pre-commit hooks. The same machinery gains a subset matrix derived from the corpus, so what the
  README claims compylr accepts is counted rather than remembered. `tests/readme.rs` enforces the
  mechanical half already; this closes the prose half.

- **No compiler behavior changes.** Nothing in the IR, the frontend, the backend, or the bridge is
  modified. If this change alters an answer, the change is wrong.

## Capabilities

### New Capabilities
- `fixture-corpus`: What the accepted and rejected corpora must contain, that every accepted fixture
  is driven, that both tiers agree with CPython, that a refused construct cannot start compiling
  silently, and that the README's subset claim is derived from the corpus rather than maintained
  beside it. This sits beside `demo`, which specifies the other verification artifact this
  repository owns.

### Modified Capabilities
- `ir-lowering`: *Diagnostics are located and non-fatal to the process* currently holds over 59
  curated fixtures. It is strengthened to hold over **arbitrary** Python — a program the subset
  cannot express must still produce a located diagnostic rather than a panic or an unlocated error,
  and that is checked against a corpus nobody wrote for the compiler.

## Impact

**Added**
- `python/fixtures/drivers/` — one driver per accepted fixture.
- `python/tests/test_differential.py` — the bridge tier, `slow` and toolchain-gated.
- `crates/compylr-host-python/tests/differential.rs` — the native tier.
- `crates/compylr-host-python/tests/corpus.rs` — the robustness walk.
- A subset-matrix generator, and its markers in `README.md`.

**Modified**
- `scripts/update_benchmarks.py` — a second generated block; `--check` covers both.
- `crates/compylr-host-python/tests/fixtures.rs` — the inverted guard over `rejected/`, and a check
  that every accepted fixture has a driver.
- `crates/compylr-host-python/tests/readme.rs` — the subset matrix joins what it verifies.
- `Makefile`, `.pre-commit-config.yaml`, and the CI workflows, so the three stay identical.
- `pyproject.toml` — `python/fixtures/drivers/` is linted, unlike the fixtures themselves.

**Unaffected, deliberately**
- Every crate under `crates/` except its `tests/`. No compiler code is touched.
- `python/fixtures/accepted/` and `rejected/` keep their contents and stay unlinted; the drivers
  live elsewhere precisely so `fixtures.rs` and `emit_quality.rs` can keep deriving their lists from
  those directories.

**Costs**
- `make check` grows by the bridge tier: one maturin build plus a call per fixture. Measured and
  reported as part of the work; if it is intolerable the tier becomes its own target rather than
  being dropped.
- Every fixture added from here on owes a driver. That is the intended tax.
